## 启用条件

窗格管理、查看器、传输订阅和快照发布都要求 `mode: "tui"`、`hasUI: true`，并且三个 Herdr 环境变量都已设置。RPC/rpc-ui 和 ACP 即使 `hasUI` 为 true 或继承了 Herdr 变量也保持不启用；`hasUI: false` 的 SDK 和 headless 会话从不启动或拆分窗格。非交互式子会话不启动查看器。在 Herdr 之外，`/dag-pane` 会报告窗格不可用；`todo` 包装仍然注册。在 Windows 上，插件会显示一次性提示。

查找 Bun 时先尝试 `bun`，然后只有在宿主可执行文件的 `--version` 输出看起来像 Bun 的语义化版本号时才尝试它；插件不会假定编译后的 OMP 可执行文件能运行查看器。找不到 Bun 时会给出警告，并跳过窗格管理。

`/dag-pane open` 可重复执行，没有窗格时 `close` 也是安全的，手动打开不受 `displayTiming` 影响。插件只管理自己记录的窗格 ID，从不按标题查找窗格。关闭操作会被记住；观察到新的运行 ID 或执行 `/dag-pane open` 时清除。作为 Atlas 镜像阶段被隐藏的待办列表也算已观察到，所以 Atlas 释放后该列表重新出现时不会清除关闭状态。用 `q` 关闭的查看器在会话重新绑定后仍保持关闭。

## 计划执行的识别

紫色运行要求存在已记录的提案、宿主中与之匹配的计划引用，以及完全一致的批准信封。用户消息里写着 `Plan approved.`，或者仅仅出现新会话事件，都不够。计划阶段在其列表完成或被放弃、且代理回合结束而没有继续时结束；之后的列表是普通的蓝色运行。

排队的合成开发者批准消息与新回合的批准提示使用相同的检查。规范的待办写入必须同时晚于实时轮询基线和已记录的批准，才能认领第一份计划列表，所以启动、切换或回退时重放的列表无法认领。在最后的代理回合边界，会先核对规范的待办写入，再检查计划列表是否已结束。受信任的排队交接通过宿主时间戳和批准文本识别，只在当前提案之后接受，并且只使用一次。保留着旧批准的上下文无法批准同一路径上的新提案。

Atlas 绑定期间，完全由镜像阶段组成的待办列表无法认领或消耗已就绪的原生计划批准，改由 Atlas 运行认领；Atlas 释放即结束这次计划执行。之后镜像阶段会以普通蓝色待办重新出现，关闭集成时也一样。Atlas 集成关闭期间到达的批准，仍由第一个新的原生列表认领。

## 图的布局

- 关键路径只使用显式依赖边，每个节点按观察到的已用时间计权，尚未开始的节点计为 1，用粗线绘制。交叉处只有它自己的线段保持加粗；与选中项共用线段时，以关键路径为准。没有显式边的运行没有关键路径。
- 默认的传递约简会在一条更长的正向路径已确定两个节点顺序时隐藏直接正向边，因此依赖所有任务的最终关口会以一次扇出挂在最后一个任务下。修正边和反向边始终绘制，关键路径的计算仍使用所有依赖。
- 长边在跳过的层中按来源共用一条竖直主干，到各个目标处分叉。汇聚到同一节点的边共用一个箭头；从同一节点发出或进入同一节点的多条边共用一个连接点。
- 节点框宽 30 列，如果缩小能让最宽的层放得下，最小缩到 20 列。如果一层的宽度不超过窗格宽度的两倍（较窄的窗格按 120 列计），就保持在一行；四个框需要 86 列，所以 50 列的窗格会把四个最终关口放在一行，并横向滚动到选中项。更宽的层在所属横带内换行，按从左到右、再从上到下排列；通往后面几行的主干会穿过前面的行。
- 每个节点位于其父节点的中位数下方。`layoutAlign: centered` 时，会重叠的兄弟节点在父节点两侧均匀展开，整个图以画布中轴居中；`left` 时，兄弟节点只向右移，整个图靠左。
- 节点模式下，上/下选择上一行或下一行中中心最近的框，左/右选择同一行中的下一个框，翻页按绘制顺序进行。折叠的层占一行摘要。平移或滚动后，视图不再跟随选中项，直到用节点模式的方向键、翻页或点击重新选中节点。切换运行或视图时从顶部开始。模式、滚动位置和显示所有边的开关不会保存。
- 运行中的任务卡片，无论是否关联节点，在有新进展之前都使用警告色边框和 `stalled` 标签。
- 子代理多次激活时，保留已完成部分的用量并加上当前激活的用量，不会重复计入累计的进度帧。运行的总用量对每个关联的子代理只计一次。
- 已报告完成的子代理，如果最终的 `task` 工具结果报告其失败或中止（例如子任务结束后隔离合并或补丁应用失败），会改为失败或中止。分离的后台任务不按此方式更正。在协作访客端，镜像来的宿主工具结果会更新视图，但不会追加 plan-execution 条目。
- 查看器运行时开启终端鼠标报告，并在所有退出路径（包括信号）上关闭。对话记录文本会去除终端控制序列；标签按显示宽度换行。读取对话记录时不会打开可写的宿主会话。

## 窗格位置

`cols < 2 * rows` 时为纵向，否则为横向。测量 OMP 区域时会把自有窗格所占的部分加回去，所以打开查看器本身不会改变方向。为避免来回切换，横向在低于 `2 * rows - 4` 时切到纵向，纵向在高于 `2 * rows + 4` 时切回横向。尺寸变化检查有 750 毫秒防抖，心跳时也会检查。

Herdr 0.9.3 无法在同一个标签页内移动窗格，所以方向改变时，插件会关闭已记录的窗格，并在新位置打开一个替代窗格（窗格 ID 会变），恢复已保存的视图状态和 socket 连接。只修改位置和大小不会重建已打开的窗格。右侧和下方直接拆分；左侧和上方先拆分再交换。Herdr 会让交换源获得焦点；`focusPane: false` 时插件会把焦点还给 OMP，但无法还原交换前聚焦在其他无关窗格上的状态。

`close-with-omp` 时，连续错过三次 2 秒一次的心跳后，查看器关闭自己的窗格并退出。`keep-open` 时，恢复快照永远不会被当作 OMP 仍在运行的证明。无论结束行为如何，`q` 总是关闭查看器自己的窗格。

关闭时会立即阻止新的窗格启动和尺寸计时器。关闭窗格、清理 socket 和写出快照共用一个 1.8 秒的时间预算；未完成的 socket 启动保持取消状态。重启时，如果自有窗格是为另一个 socket 启动的，或是没有 socket 的旧记录，会被关闭并重建。

设置修改何时生效：`displayTiming` 在下一次判断时生效，不会关闭已有窗格；宿主关闭时使用当前的 `finishBehavior`，但查看器失去心跳时的行为在启动时就已确定；位置、大小和 `focusPane` 在下次打开或因方向改变重建时生效；`stalledAfterSeconds` 需要重启 OMP 才会作用于任务来源；`todoDependencies` 在重新加载设置后的工具调用中生效；重新加载 `atlasIntegration` 会开关消费者和镜像去重；颜色和 `layoutAlign` 在下一次发布快照时生效；`followTheme: false` 保留最后一次采样的配色；`viewerRuntime` 在下次启动查看器时生效。每次自动打开判断（包括心跳时）也会读取设置，无效字段在每个项目范围内只警告一次。

## Atlas 契约

查看器消费 `omo-prometheus` 发布的 `pi.events` 契约，事件定义见 [omo-prometheus 参考文档](../omo-prometheus/REFERENCE.zh.md#herdr-dag-契约)。没有启用的生产者时，查看器会报告 Atlas 集成不可用，原生待办和任务视图照常工作。

`atlas:snapshot` 保持 `v: 1`。行类型 `task`、`discovered`、`fix`、`gate` 和 `delivery` 分别排入 Tasks、Discovered、Fixes、Final gates 和 Delivery 横带。新发现行以修正边样式从其 `origin` 连出；修正行仍指向其来源关口。这些来源边不代表调度依赖。可选的 `tier: "light" | "heavy"` 显示为 LIGHT/HEAVY 徽标，可选的 `verification: { status: "pending" | "running" | "passed" | "failed" }` 在节点和选中详情中显示为 `verify: <status>`；不含这些字段的快照仍被接受。时间线类型还包括 `discovered`、`implemented`、`verify_started`、`verify_passed` 和 `verify_failed`。查看器从不把时间线事件当作节点状态或调度依据，未知类型不产生影响。验证子代理使用行的当前 `attempt`，由该行的验证状态标识。

## 待办依赖边

包装会保留原生的修改、详情、钩子、批准、批量失败和渲染行为。原生操作出错时不记录依赖边。删除或修改任务会清理相关的边，`init` 会开始新的一代。

## 本地存储

持久文件位于 `ctx.sessionManager.getSessionDir()/herdr-dag/<sessionId>/`；内存会话（`--no-session`）使用 `os.tmpdir()/omp-herdr-dag/sessions/<sessionId>/`。文件为带版本的 JSON，通过临时文件替换写入。`snapshot.json` 和 `pane.json` 为版本 2，加载时会升级版本 1，保留恢复数据、所有权和关闭状态。没有 socket 路径的 v1 窗格记录只会重新启动其记录的窗格，从不接管其他窗格。`view-state.json` 保持版本 1；未知或更新的版本会被忽略并替换。

| 文件 | 保存的字段 |
| --- | --- |
| `snapshot.json` | `version`、会话 ID/名称、代、连接标志、时间戳、运行、任务卡片、主题配色、三种来源颜色、Atlas 可用性，以及可选的 `layoutAlign`（旧快照中没有，按居中渲染）。 |
| 运行对象 | ID、来源、标题、代、节点、边、创建/更新/结束时间戳，以及完成数/总数/已用时间/token/费用统计。 |
| 节点对象 | ID、标签、状态、横带/名称、详情、开始/结束时间戳、代理、关联的任务 ID、停滞标志，以及可选的分级和验证状态。边包含 `from`、`to` 和 `kind`。 |
| 任务卡片 | ID、父任务/节点 ID、代理、状态、可选的停滞标志、描述、当前工具/参数、最近输出、已完成/当前激活的合计（token、费用、时长）、激活次数、模型、重试次数/上限/错误、可选的 `completionPercent`（宿主对运行中子任务给出的 0–100 完成度估计，显示在状态旁；旧快照或宿主没有估计时不存在）、对话记录路径、开始/结束时间戳、分离标志、深度和活动可用性标志。 |
| 主题配色 | 文本、muted、dim、accent、success、error、warning、边框、强调/弱化边框，以及可选的背景色。 |
| `pane.json` | `version`、拆分/打开阶段、已知时的窗格/标签页 ID、宿主窗格 ID、方向、位置、启动时间戳、可选的启动 socket 路径和关闭标志。 |
| `view-state.json` | `version`、折叠的运行 ID、视图（`dag`、`tasks`、`transcript`）、选中的运行 ID 和关键路径开关。 |

宿主会话中还保存了自定义条目：`omp-herdr-dag:plan-execution`（`v`、已提出/执行中/空闲状态、可选的计划路径和运行 ID、时间戳）和 `omp-herdr-dag:todo-edges`（`v`、代、task/after 记录）。插件不收集任何凭据。对话记录的内容不会被复制，查看器直接读取现有文件。

实时传输使用位于 `os.tmpdir()/omp-herdr-dag/<hash>.sock` 的 Unix socket，按 Herdr 宿主窗格和进程 ID 生成，放在私有目录中。socket 增量会被合并，序号不匹配或积压过多时进行完整重新同步。快照只用于重启后的恢复。

会话启动时，`retentionDays` 会清理其他由插件拥有、且最新文件早于截止时间的会话目录。它从不清理当前会话、宿主对话记录、Atlas 计划包，或宿主会话中的自定义条目。

插件自己不发布插件状态快照；客户端可以从宿主 RPC 数据读取原生待办和子代理状态，从 `omo-prometheus` 的快照读取 Atlas 状态。
